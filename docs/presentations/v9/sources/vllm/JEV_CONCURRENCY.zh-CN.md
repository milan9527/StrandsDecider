# Decider vLLM 与 Jev：并发性能对比

[English](JEV_CONCURRENCY.md) | 简体中文

2026-10-13。Decider 固定批次 token 预算 **8192**，与 Jev API 使用同一测试客户端、相同 20 条业务输入，比较 1–128 并发的吞吐与端到端延迟。

**本文 Decider 一栏使用 vLLM 适配版本，并非原版串行实现。** 单张 L4 GPU 运行在按需 EC2 `g6.xlarge` 上，测量对象是独立公网推理服务；配套支付演示尚未切换到该服务。此前 Decider 自身各轮实验另见 [Decider vLLM 性能总结](VLLM_PERFORMANCE.zh-CN.md)。

Decider：**10,239/10,240** 次正式请求成功；Jev：**10,240/10,240**。预热分别为 560、560 次，失败分别为 0、0 次，均不进入正式性能统计。未触发停止条件，所有计划档位均完成。

## 失败与计时差异

主扫描 Decider 在 64 并发发生一次 HTTP 502（`refund/verify`，index 1271，客户端 48.5 ms），响应没有后端请求 ID；没有定位该失败的具体来源，也没有重试覆盖原记录。

128 并发中，Decider 有 10 次 `underpaid/approve` 的置信度从原版参考 0.5917 变为 0.6119，差值 0.0202 超过 0.02。选择仍是 `approved`，候选概率最大差 0.0151。保留数值失败，不调整阈值；这些是成功 HTTP 响应，与上面的 HTTP 502 分开统计。

Decider 128 并发的客户端平均 / P95 为 3981.9 / 11236.8 ms，服务端自报为 108.5 / 187.1 ms。服务端计时从请求解析后开始，包含预处理、引擎排队和计算；差异说明本档有大量耗时不在该计时范围内，但本轮没有将客户端、连接池、网络、CloudFront 与请求解析分别剖析，不能归因于某一层。

## 输入与返回

| 模型 | 输入 token 范围 | 平均输入 | 输出 token 范围 | 平均输出 |
|---|---:|---:|---:|---:|
| Decider | 304–445 | 373.9 | 1–1 | 1.0 |
| Jev | 575–744 | 657.0 | 33–79 | 55.0 |

输入为四个支付场景 × 五个独立业务步骤，每条在每档重复 64 次，按同一顺序轮流发送。请求的业务事实、问题和候选条件完全相同；Jev 额外指定 `model=jev-latest`，实际返回版本为 `jev-1.13.0`。

Token 数为各服务返回的统计，不假定两者分词、内部模板或用量口径相同。Decider 的 `output_tokens=1` 表示一个决策问题，不表示完整 JSON 只有一个文本 token。Jev 的输出用量原样保留，不据此推断其内部生成方式。

Decider 与固定原版参考的数值对齐通过 **10,229/10,239** 次，阈值仍为 0.02。两模型同输入且双方成功的 10,239 对请求中，候选 ID 相同 9,215 对；这是动作一致性，不是业务准确率。没有将 Jev 的概率与 Decider 的概率按同一校准尺度比较。

## 测试路径与配置

- Decider：客户端 → CloudFront → 私有 VPC 源站 → EC2 `g6.xlarge` / NVIDIA L4 → vLLM 0.31.0。模型为同一 v19 权重；批次预算 8192、引擎序列上限 128、HTTP / 问题准入 256、显存目标 0.7。
- Jev：同一客户端 → `https://api.typesafe.ai/v1/systemone`，直接调用供应商 API，绕过支付演示的 ECS 两调用槽与 Lambda 转发。未修改原支付演示配置。
- 两者分开施压，每个并发档位轮换先测的模型；固定数量 worker 收到完整响应后立刻补下一个请求，不自动重试。HTTPS/HTTP1.1 连接池支持最高并发，连接复用方式相同。
- 每档先预热 `max(20, 2 × 并发数)` 次；延迟为客户端发起请求至读取完整响应，包含网络、服务端排队与处理。P50/P95/P99 使用 nearest-rank。
- 客户端 HTTP 超时设置 40 秒、连接超时 8 秒；Decider 服务端推理期限 25 秒，Jev 内部期限未知。Jev 若未返回 `latency_ms`，不补算或伪造纯模型耗时。
- 任一 400/401/403/413/422/429，或同阶段五次其他失败，会停止该模型的新提交和更高档位，保留已在途响应。预热失败也停止该模型；不换 key、不重试或规避限额。
- 输入是固定业务状态，不执行支付、不把前一步选择写回下一步，也不进行模型微调。

这是两种部署路径的 **API 服务性能**，不是相同硬件上的模型内核竞赛。Jev 的底层硬件、副本数、调度及重复输入缓存策略未知。固定请求量、重复这 20 条输入的短时闭环结果不能作为供应商最大容量或生产 SLA；此前经过 ECS/Lambda 的 Jev 数据不混入本表。

## 状态与复现

Decider 测试前后参数一致，GPU 持续运行；最终公网鉴权和真实推理检查通过。本次没有更改生产服务代码或并发配置。

下列命令调用真实服务；服务端须已配置为本报告参数，脚本不会替你修改配置：

```bash
uv run --no-sync python scripts/benchmark_jev.py \
  --credentials .deployment/api-credentials.json \
  --jev-key-file ~/ai/jev/jevkey.txt \
  --requests 1280 --levels 1 2 4 8 16 32 64 128 \
  --output artifacts/jev-comparison-new
```
