## 本次新采集：四场景、三模型

2026-10-12 **06:19 UTC 起**，现网 `triple1` / API `20261012-triple1`；Decider v19 在 EC2 `g6.xlarge` / L4 常驻，Jev 实际返回 `jev-1.13.0`，Bedrock 为 `us.openai.gpt-6.1-sol`、reasoning `low`。

每场景运行一次「优化流程」，共 **60 次真实模型调用全部成功**。每步三个模型收到相同业务 payload，GPT 另有输出格式要求。五步原始建议采集后分别执行，不自动补齐外部证据。

### 行为和实际结果

| 场景 | Decider | Jev / GPT | 实际结果 |
| --- | --- | --- | --- |
| USDC 未到账 | 等待确认、审批通过、挂起跟进 | 同样选择 | 确认仍为 3/12，无入账或结案 |
| USDT 少付 | 确认已达 20/12，却选择等待确认 | 要求补足 0.20 USDT | 保留 Decider 错误；三侧资金均挂起 |
| 稳定币退款 | 地址未验证却选择检查通过 | 验证退款地址 | 执行器将 Decider 动作调整为验证地址；不退款 |
| 商户结算 | 识别超时、升级工单、持续跟进 | 同样选择 | 尚未收到结算款，不对账结案 |

三侧均完成各场景五步处理，但初始证据下均 **0/4 完成资金业务**。Decider 有两处参考差异，其中一次触发动作保护调整；应用纠正不计为模型答对。

少付误选时 Decider confidence 为 **0.8138**，退款误选为 **0.2524**。高置信也可能错，不能只靠阈值代替业务校验。模型训练分布、条件组合和输出机制可能影响表现，但本次输出无法确认内部错误原因。

### 单独的闭环运行

USDC 闭环另有 **18 次真实决策**：三侧各六次决策、一次模拟确认事件，最终都生成 129 USDC 模拟收款账本并结案。这些调用不进入前述同输入速度表。

Decider 首次核验误选 `settlement_verified`。执行检查发现确认不足，保留等待状态；模拟器将确认数从 3 改为 12，再把新证据与执行反馈交给模型。随后三侧均重新核验、入账、结案。中途错误保留，最终完成不代表每次判断正确。

## JevBench：公开结果及使用边界

来源：[Benchmark Heaven API board](https://benchmarkheaven.com/jev-models/api)，2026-10-12 抓取，页面版本 **v1.7.46**，27 个排名条目。本项目引用其发布结果，**没有重跑 JevBench**。

| 该榜单模型 / 配置 | 权重 | 综合分 | 能力 I | 校准 C | p50 | 美元 / 千次决策 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Sage 1.3.0 | 闭源 | 74.0 | 65.6 | 91.6 | 0.152 s | 0.025* |
| Liquid d1 | 闭源 | 73.0 | 62.1 | 86.8 | 0.268 s | 0.017 |
| Jev 1.13.0 | 闭源 | 71.5 | 63.6 | 90.6 | 0.239 s | 0.032 |
| GPT-6 Luna · low | 闭源 | 40.5 | 96.6 | 99.0 | 1.854 s | 0.108 |
| GPT-5.6 Luna · low | 闭源 | 21.4 | 94.1 | 94.9 | 1.588 s | 0.213 |
| Gemini 3.1 Flash-Lite | 闭源 | 16.9 | 58.6 | 60.9 | 0.957 s | 0.230 |
| DeepSeek V4.1 Flash | 开放权重 | 7.1 | 94.7 | 100.0 | 2.038 s | 0.480 |
| Qwen3.8 27B | 开放权重 | 0.0 | 96.4 | 100.0 | 7.095 s | 2.178* |

`*` 为榜单标记的估算成本。价格是标价与用量建模或历史估算，不是本项目账单。开放权重模型在此也通过托管端点评测，例如 Qwen 的 Chutes TEE 服务；不要混同统一硬件的自部署榜单。

- **综合分不是准确率**：四轴等权调和平均，并对 Intelligence、Speed、Cost 中低于 50 的轴应用额外惩罚。因此 Qwen 综合 0.0 不表示答不对问题，其能力分仍为 96.4。
- **能力与综合排名分开看**：Jev 综合第 4；所列强通用模型的能力分更高，但延迟和成本不同。
- **题池和时间不同**：榜单汇总全量 1,500 题及 600 题 API 重测等值调整结果，并保留历史测量日期；不是同一天同网络的一次统一重跑。
- **与项目模型不同**：API 榜单没有本项目 GPT-6.1 Sol、Strands Decider v19 或 Claude 的对应条目，不补造分数。其他名为 `decider-*` 的项目不能当作 Strands 模型。
- **Decider 另有官方报告**：模型卡公开子集 `167/231 = 72.29%`，不是当前 API 榜单的能力分或综合分，不能直接混排。
- **延迟不能简单相减**：JevBench 的 Jev p50 为 239.1 ms，本项目为 404.9 ms；任务、网络、测量位置不同，差值不等于 Lambda 开销。

## Decider 优化：已验证与待验证

第 24–25 页复用 v6 的 **2026-10-11 独立前后对照**：精简无关字段、明确候选适用范围，使参考一致由 14/20 改善到 18/20，保护调整由 4 次减少到 1 次。未修改权重；字段和条件表述同时变化，不能单独归因。Jev 没有参加这份前后对照。

第 26–28 页给出下一阶段方案，均明确标记为建议：

1. 针对少付与退款错误，构造只改一个条件的最小对照、边界数字、语言和候选顺序变体。
2. 按场景拆分判断、精简适用候选；改动同样应用到三个模型，另记录效果。
3. 积累去标识业务样本和人工标签，按案件、模板簇及时间划分训练、验证、保留测试集。
4. 必要时沿用官方训练链路适配 LoRA / Pointer Head，保留通用任务、`noul` / `score` 回归；教师模型仅辅助标注。
5. 在独立验证集做概率校准和路由阈值选择；生产评估覆盖风险错误、完成率、吞吐、失败和总体成本。

当前尚未执行领域微调或验证这些新方案；PPT 没有声称新的提升幅度。
