## Jev 场景测试：延迟、业务效果与成本

从已经保存的真实请求重新计算，没有新调用模型。下表延迟为**客户端单次 API RTT 中位数**，费用为 Jev 响应中的实际输入 token × **$0.042 / 百万 token**，输出免费。

Jev 直连 API，Decider 经现有应用网关访问原版模型服务；这里比较完整 HTTP 调用，不能解释为纯 GPU 前向耗时，也不是 vLLM 的并发测试。

| 场景 | 业务结果：Jev / Decider | Jev RTT | Decider RTT | Jev / 千次 API | 结论 |
| --- | --- | ---: | ---: | ---: | --- |
| Skills | 65/65 / 50/65 个问题与参考一致 | 119.9 ms | 164.6 ms | $0.02133 | 分类和局部选择两者接近；证据核验、完成检查优先试点 Jev |
| 真实浏览器 | 10/10 / 4/10 任务完成 | 137.0 ms | 227.3 ms | $0.08003 | Jev 更适合本批多步文字 / DOM 操作，结束前仍检查实际目标 |
| 金融初筛，原始顺序 | 28/30 / 22/30 | 138.3 ms | 97.4 ms | $0.03133 | Jev 业务结果更好但延迟更高；两者均误判合并存款额度，金额规则应由程序复核 |
| 政策路由，两种顺序 | 46/64 / 25/64 | 137.4 ms | 211.4 ms | $0.06103 | Jev 更好但仍漏能力和预算条件；可做任务分流与候选建议，不能独立承担硬约束验收 |

**本批支持的结论是：Jev 在证据核验和多步完成方面更值得优先试点，成本低；延迟并非每个场景都优于 Decider。金融和完整模型路由仍需要确定性检查。** 这不是通用能力排名或生产准确率。

成本按“API 请求”计算。Skills 一个请求可包含多个问题；浏览器一个任务会调用多次模型。十次 Jev 浏览器任务共有 36 次 API 调用、68,601 输入 token，模型费合计约 **$0.002881**。若保持相同任务配比，约 **$0.288 / 千条任务**，不含浏览器、后端和网络费用。不能把每千次 API 的 $0.080 当作每千个完整任务的费用。

浏览器端到端任务耗时包含页面加载、等待和操作，与上述 API RTT 分开记录。Skills 首次 Decider 六问题请求为 13.511 秒，仍保留在原始记录和平均值中；本版没有删掉慢请求或推断其原因为冷启动。

| Jev 实测用量 | 请求数 | 输入 token 合计 | 本批按公开价估算 |
| --- | ---: | ---: | ---: |
| Skills | 32 | 16,252 | $0.000683 |
| 浏览器 | 36 | 68,601 | $0.002881 |
| 金融，原始顺序 | 30 | 22,381 | $0.000940 |

金融只取原始顺序，与本页 28/30、22/30 的业务成绩对应；政策路由保留两种顺序，不含后续自然语言诊断。这些是公开价估算，不是账单。Decider 是固定 GPU 费用，不能把一小批请求的运行时间当作完整部署成本。

游戏保留单独口径：自然语言版 Jev 50 块 / 19 行，Decider 43 块 / 2 行；每落点平均耗时 **251.1 / 1414.5 ms**，一次落点可包含多次请求。只测一个种子；现有游戏汇总没有 token usage，**不套用支付输入估算游戏成本**。

## 成本交叉图：On-Demand、1 年 RI、Jev

沿用 2026-10-15 AWS Price List 查询：`us-east-1 / Linux / Shared / g6.2xlarge`，单台常驻，按年均 730 小时/月。

| 方案 | 计算方式 | 月均计算费 |
| --- | --- | ---: |
| On-Demand | $0.9776 × 730 小时 | **$713.65** |
| 1 年 Standard RI，无预付 | $0.63642 × 730 小时 | **$464.59** |
| Jev | 实际输入 token × $0.042 / 百万 | 随用量增长 |

选择**无预付**，让两种 EC2 方案都以持续小时费比较；没有把全预付的摊销金额冒充每月账单。RI 承诺整个一年，停止实例仍付费；区域 RI 不预留容量。

两张图中，EC2 为两条水平线，Jev 为随调用量上升的斜线：

| 工作负载 | 实测 Jev 平均输入 | Jev / 百万工作单元 | 与 1 年 RI 的交点 | 与 On-Demand 的交点 |
| --- | ---: | ---: | ---: | ---: |
| 支付单次决策 | 656.95 token / 次 | $27.5919 | **1,684 万次/月** | **2,586 万次/月** |
| 完整两步路由 | 2,805.75 token / 条 | $117.8415 | **394 万条/月** | **606 万条/月** |

在一台实例能够承载、业务质量达标的前提下：

- **低于 RI 交点**：Jev 调用费低于两种 EC2 计算费。
- **两个交点之间**：1 年 RI 最低，Jev 仍比 On-Demand 低。
- **高于按需交点**：两种 EC2 计算费都低于 Jev 调用费。

这些交点只比较计算/API费用，未计 EBS、网络、应用、运维、冗余、税和下游模型执行。`g6.2xlarge` 未做本批容量实测，不能将短时 `g6.xlarge` 压测直接当作其长期容量。

## 各自适用场景

**Decider**：候选明确的分类、工具选择、语义分流等高频局部判断，尤其适合需要自托管、可控部署和低单请求延迟的系统。本批分类 13/13、局部动作选择 10/10，与 Jev 相同；证据与完成检查仍需补强。稳定流量下再评估 1 年 RI，并计入运维和容量。

**Jev**：优先用于本批更有优势的证据核验、多步文字浏览器任务，以及流量小或波动明显、希望按量付费的候选决策。独立 vLLM 对照中，Jev 32 并发为 240.94 请求/秒、Decider 为 30.61；单并发平均延迟则为 Jev 126.5 ms、Decider vLLM 55.4 ms。吞吐优势、单次延迟和业务正确性是不同维度。

**GPT**：适合开放式回复、代码生成、复杂异常处理；这些是用途建议，项目尚未对开放任务做三模型质量验证。同一支付候选批次中 GPT 为 20/20 与参考一致，平均后端耗时 1116.7 ms；高频短选择需权衡延迟。当前支付记录没有 GPT 费用值，本版没有编造其费用对比。
