## 结算分析实际结果

请求原文：

> 商户 A 应结算 12000 USDC，实际收到 11880 USDC，手续费为 0.8%，另有 24 USDC 暂扣。分析结算差额及其原因。

2026-10-15 新批次，三模型均选择 `reasoning`；同阶段输入与候选指纹相同。6 次独立预热不计入正式统计，正式包含 **6 次路由决策和 3 次目标执行**。

| 路由决策器 | 所选目标 | 两步路由合计 | 目标执行 | 实际结果 |
|---|---|---:|---:|---|
| Decider | Claude Opus 5 | 477.6 ms | 38.95 s | 返回最终答复，核算出 96 手续费 + 24 暂扣 = 120 差额 |
| Jev | Claude Opus 5.5 | 792.5 ms | 40 秒响应等待上限触发 | 路由成功，目标执行返回 HTTP 504，未得到答复 |
| GPT-6 Sol · low | GPT-6.1 Sol | 1797.6 ms | 23.25 s | 返回最终答复，核算一致，并说明手续费基数假设 |

两份答复都将暂扣与最终费用区分开。Opus 5 扩展了会计处理、暂扣的可能原因和待核实事项；GPT 的答复更聚焦本题。只核对本题金额和暂扣含义，不把 Opus 5 的全部扩展会计建议计作已验证。

**Jev 本次成功完成路由，超时的是它选中的目标 Opus 5.5。** 没有自动重试、降低档位或换模型。超时响应没有完整生成时长和 token usage，因此没有伪造精确耗时或将费用记为零。不能把这个单次目标超时推导为 Jev 决策失败。

目标执行沿用候选的评测 **max effort** 配置，最多 4096 输出 tokens，SDK 响应等待上限 40 秒。GPT 路由器的 **low** 与目标模型的 **max** 是不同角色。三个目标依次各调用一次，不是并发性能测试，也不是稳定延迟结论。所有操作仅生成分析文本，没有账务或资金操作。

四任务汇总仍使用原 2026-10-13 批次；新增结算实测单独展示，没有将两批耗时混入平均值。

## 计费模式

| | Jev API | Decider on EC2 · 按需 | Decider on EC2 · 一年 RI |
|---|---|---|---|
| 计费依据 | 实际输入 token，包含问题和候选 | 实例运行时长 | 一年用量承诺换折扣 |
| 公开价格 | $0.042 / 百万输入 token；输出免费 | g6.2xlarge：$0.9776/h | Standard、无预付：$0.63642/h |
| 没有请求 | 没有模型调用费 | 实例运行仍计计算费 | 停止实例仍付承诺 |
| 每月 100 万次支付决策算例 | $27.59 | 730h 常驻：$713.65 | 730h 月均：$464.59 |

价格快照为 2026-10-15，EC2 为 us-east-1 / Linux / Shared。算例采用既有实测 Jev 支付输入均值 **656.95 token/次**，不是本次目标生成的 token 用量。EC2 计算费不是按请求或 token 计费；单次分摊取决于利用率。

单台能否承载负载需另行验证；价格算例不代表已测得 g6.2xlarge 容量。应用、EBS、网络、目标生成模型、高可用和运维费用另计。一年 RI 是计费承诺，不是另一种推理部署；区域 RI 不预留容量。
