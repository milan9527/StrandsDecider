# README 演示项目：决策模型能组成哪些应用

此前的技能模板实验只验证了结构化判断，没有复现 README 展示的浏览器、俄罗斯方块、音乐工作站等应用。这些演示应当单独分析，不能用模板实验的 Jev 65/65、Decider 50/65 代替应用完成率或效果。

本页于 2026-10-12 核对上游 README、项目 README 及相关测量说明。以下数字明确归属于**原作者报告**；本项目尚未执行这些应用的 Jev / Decider 对照。

## 六个演示与业务用途

“可对应的业务”是根据实现方式提出的应用方向，不是已经验证过的业务效果。

| README 演示 | 决策模型负责什么 | 其他组件负责什么 | 可对应的业务 |
| --- | --- | --- | --- |
| [浏览器自动化 Jev Ultrafast](https://github.com/browser-use/jev-ultrafast) | 从当前 DOM 中选操作及目标，如点击、输入、选择、等待、完成 | 浏览器读取页面、执行动作、检查页面变化；文本模型生成要输入的文字；独立检查任务结果 | 机票或商品检索、后台查询、表单操作、网页测试 |
| [俄罗斯方块 Jev Tetris](https://github.com/thelau/jev-tetris) | 根据合法落点的文字描述，对消行、空洞、堆叠高度等维度给出偏好 | 游戏代码搜索可达落点、计算几何与消行；融合模型分布、执行落子、渲染 | 游戏策略演示、仿真决策、带明确合法动作集的训练环境 |
| [鲸背城市](https://x.com/gokayfem/status/2101022590722810271) | 在当前模拟世界中选择合法动作 | 规划模型设计世界；模拟器更新状态；渲染工具生成画面 | NPC 决策、经营模拟、情景推演；迁移到真实资源调度需另测 |
| [MIDI 作曲 Jevthoven](https://github.com/cocktailpeanut/jevthoven) | 选择节拍、速度、乐器、和声、片段意图和逐小节模式 | 程序把选择转换成音符，提供钢琴卷帘编辑、播放、保存与 MIDI 导出 | 可编辑配乐草稿、游戏循环音乐、创作辅助 |
| [代码审查 Jev Review](https://github.com/devagrawal09/jev-review) | 筛风险、选文件和证据片段、分类问题机制、评估严重度及分派审阅者 | Git/文件读取、分阶段编排、阈值策略、报告面板 | PR 预筛、代码库审查任务排序、审查人员分工 |
| [决策游乐场 Jev Explained](https://github.com/davila7/jev-explained) | 对示例输入回答 Noul、Choice、Score | 页面展示请求、概率、耗时和消费策略 | 技术教学、问题设计、流程原型验证；其中交易例子不代表投资效果验证 |

这几个项目展示的是不同应用形态：浏览器操作、连续游戏控制、模拟世界、可编辑创作和开发工具。它们的共同点是**程序准备状态与候选，模型判断，程序执行并观察结果**。连续运行时，下一轮必须使用实际执行后的新状态。

## 原作者报告的实际效果

### 浏览器自动化：已经有完整任务测量

核对版本：`1231850a0bf1a0c0341fe408ef1668dbbfdfac46`。

原作者报告的 Google Flights 任务为：查找苏黎世至伦敦的单程航班，直到正确条件下的航班结果可见，不选购或订票。

- 演示录制的任务耗时为 **7.073 秒**，包含 17 次 Jev 请求、两次文本辅助模型调用、浏览器操作和等待。
- 同一任务、同一浏览器配置下，两种运行时交替执行三次，各 **3/3** 通过独立结果检查；中位耗时从 **9.450 秒降至 7.092 秒**。
- 这是浏览器运行时代码优化前后的比较，两个版本都使用 Jev；不是 Jev 与 Decider 或其他决策模型的速度比较。
- 另有 Wikipedia 指定文章打开 **2.798 秒**、本地酒店筛选任务 **1.896 秒**的独立冒烟记录。
- 初始浏览器设置、初始导航及运行后独立复核不在任务计时内。支持范围主要是常见 HTML/ARIA 控件，未覆盖任意 iframe、canvas、上传、多标签页等复杂网页行为。

业务含义：浏览器自动化是决策模型值得验证的应用方向。模型可以减少每一步生成完整动作脚本的需要，但端到端效果仍依赖 DOM 提取、文本填写、等待策略、页面时效检查和结果核验。

来源：[README](https://github.com/browser-use/jev-ultrafast/blob/1231850a0bf1a0c0341fe408ef1668dbbfdfac46/README.md)、[测量边界与完整尝试](https://github.com/browser-use/jev-ultrafast/blob/1231850a0bf1a0c0341fe408ef1668dbbfdfac46/docs/performance.md)。

### 俄罗斯方块：能发挥作用，但没有胜过简单基线

核对版本：`9869b602965cf002afff766013f8c068846d36aa`。

原作者在三组固定方块序列上报告：

| 策略 | 三组消行数 |
| --- | --- |
| 随机选择 | 0 / 0 / 0 |
| 打乱 Jev 概率与落点对应关系 | 0 / 0 / 0 |
| Jev 原策略 | **23 / 115 / 23** |
| 同样描述上的 23 行关键词规则 | **118 / 73 / 118** |
| El-Tetris 启发式 | **118 / 118 / 116** |

打乱模型偏好后表现退化，说明模型排序确实影响游戏过程。但关键词规则整体表现更好，模型效果也随序列明显波动。作者还说明配置与权重是在同样三组序列上调出的，属于样本内结果。

业务含义：它是很好的“受限动作决策”演示，不能证明模型优于专门算法。对于规则清楚、可计算目标明确的游戏或调度任务，应同时测试随机、简单规则和已有优化算法。

来源文档存在一处口径不一致：README 写 300 块上限，`findings.md` 开头写 200 块，但表中有 300 块。因此这里只转述各表一致的消行数，不据此推算效率倍数或留出集成绩。

来源：[README](https://github.com/thelau/jev-tetris/blob/9869b602965cf002afff766013f8c068846d36aa/README.md)、[基线、调参影响与失败分析](https://github.com/thelau/jev-tetris/blob/9869b602965cf002afff766013f8c068846d36aa/docs/findings.md)。

### MIDI 作曲：流程可运行与音乐好听是两个指标

核对版本：`e5e0c67d8bae92f96c9ce05138f55c3ab72c6aac`。

README 展示了从文字意图到可编辑多轨作品的流程。模型逐步选择音乐部件，代码生成音符与 MIDI。原作者说明，16 小节、4 音轨约需要 **75–80 次模型调用**，完整作品可能需要分钟级时间。

其限制说明明确没有建立音乐质量结论；单元和集成测试主要验证结构、确定性与协议。早期 `VALIDATION.md` 只对应参考包交付，记录零次真实 API 调用，不能拿该记录证明后来整个应用已经完成真实模型音乐质量评估。

业务含义：可用于可编辑音乐草稿与交互创作原型。需要另测作品可导出率、编辑约束、耗时和用户盲听偏好，不能用“返回合法音符”替代创作质量。

来源：[README](https://github.com/cocktailpeanut/jevthoven/blob/e5e0c67d8bae92f96c9ce05138f55c3ab72c6aac/README.md)、[限制](https://github.com/cocktailpeanut/jevthoven/blob/e5e0c67d8bae92f96c9ce05138f55c3ab72c6aac/KNOWN_LIMITATIONS.md)、[早期交付记录](https://github.com/cocktailpeanut/jevthoven/blob/e5e0c67d8bae92f96c9ce05138f55c3ab72c6aac/VALIDATION.md)。

### 其他三个演示的证据边界

- **鲸背城市：** 此次核对的是合集的作者视频入口与素材说明，未运行模拟器，未获得可复现的量化对照。[合集对应场景](https://github.com/wuyoscar/jev-skill/blob/48ba080ab973f11247d6686dc2e3c1d117d76ca3/README.zh.md#sc-world-video)及[素材来源](https://github.com/wuyoscar/jev-skill/blob/48ba080ab973f11247d6686dc2e3c1d117d76ca3/docs/media/README.md)可用于继续查证。
- **Jev Review：** 项目明确把发现定义为审阅线索，没有接入完整编译诊断、静态分析和代码索引；此次未见足以建立缺陷准确率的测量。我们此前的 `assert True` 样例不是这个项目的复现。[核对版本 README](https://github.com/devagrawal09/jev-review/blob/31f89602797fb7bea007f8a480bf368bf564954e/README.md)。
- **Jev Explained：** 展示垃圾邮件、市场快照、工具调用守卫和收件箱分流等可编辑请求。适合教学和验证输入输出协议；页面上的速度、置信度展示不能直接证明通用可靠性。[核对版本 README](https://github.com/davila7/jev-explained/blob/5cbe35e04609112be77b1bd447bd79b3bde7980b/README.md)。

## 与本项目已测结果的关系

| 验证对象 | 已有证据 | 仍然不能回答的问题 |
| --- | --- | --- |
| 本项目技能模板 | Jev / Decider 各 32 次真实请求，65 项可判定预期分别符合 65 / 50 | 浏览器完整任务、游戏长期策略和音乐质量 |
| 本项目支付沙盒 | 两模型各 20 次真实决策，符合业务参考 20 / 18 | 真实资金执行和生产业务正确率 |
| 浏览器原项目 | 作者的独立任务核验、计时、失败与优化记录 | Decider 接入相同浏览器后的效果 |
| 俄罗斯方块原项目 | 作者的 Jev、随机、打乱概率、关键词和启发式对照 | Decider 在同样候选、序列和预算下的效果 |
| 其余演示 | 实现说明、示例或视频；各自有不同验证边界 | 本项目的双模型端到端效果 |

如果要补齐“这些演示在项目现有两模型上实际如何”的证据，浏览器应比较相同任务的完成率、错误动作、调用数和总耗时；俄罗斯方块应比较相同方块序列的消行、存活步数、非法动作、耗时及规则基线。还需先检查候选数量与输入长度：当前应用的 Choice 最多 12 个候选，而俄罗斯方块作者报告候选数最高达到 37，不能直接替换地址就声称完成公平接入。
