# 决策模型适合什么场景：基于本项目实测

README 的应用范围还包括**浏览器自动化、俄罗斯方块、鲸背城市、MIDI 作曲、代码审查和决策游乐场**。这些项目的模型分工、业务方向与原作者测量已补充到[演示项目分析](DEMO_PROJECTS.zh.md)。浏览器作者报告约 7.1 秒完成一次航班搜索；俄罗斯方块作者报告 Jev 优于随机，但整体不如简单关键词规则。这些是原作者结果，本项目尚未复现它们的 Jev / Decider 对照。

当前结果支持优先试点**工单分类、工具或模型路由、有限动作选择、上下文相关性筛选**。这些任务能提供清晰的证据和有限候选，模型输出也容易交给程序检查。任务完成验收、代码质量判定、缺失证据处理和重要审批，需要更强的独立校验；本轮 Decider 在这些判断中已有明显偏差。

以下使用已完成的真实模型请求，没有追加模型调用。将技能实验全部 65 个可判定问题按用途重新分组，未修改标签，也未删除错误样本。分组是事后分析，不是预先设计的独立场景基准。原模板有歧义的 3 个问题继续单列、不计分。

## 支付业务的独立实测

另一个已完成批次使用四个支付案例，每个案例五步：收款未到账、少付、退款、商户结算。每步向 Decider、Jev 和 GPT 提供相同输入，再应用各自建议并经过共同的沙盒执行保护。

| 模型 | 成功请求 | 符合业务参考 | 执行保护调整 | 平均后端耗时 |
| --- | ---: | ---: | ---: | ---: |
| Strands Decider | 20/20 | 18/20 | 1 次 | 107.8 ms |
| Jev | 20/20 | 20/20 | 0 次 | 457.2 ms |
| GPT-6.1 Sol | 20/20 | 20/20 | 0 次 | 971.1 ms |

Decider 的两个偏差是：已经达到确认要求但少付时，建议继续等待链上确认；退款地址还没核验时，判断审批通过。后者被执行器调整为验证地址。

这支持把决策模型用于**支付客服分流、核验步骤推荐、等待/升级/跟进选择**，同时由确定性代码检查金额、确认数、地址、审批与账本状态。固定金额比较或权限检查已有精确规则时，直接用代码更容易验证；模型主要处理文字诉求和语义分流。

三个模型都处理完各案例的五步，但初始输入本来就缺少资金或结案条件，所以均为 **0/4 完成资金业务及结案**。保持待处理、等待补款或跟进，可能正是正确的业务结果，不能把“尚未完成业务”一律算作模型失败。这批只做沙盒执行，没有真实转账或退款。

支付数据来源：[完整三模型实测](../../docs/results/triple-2026-10-12.json)、[业务差异解释](../../docs/MODEL_COMPARISON.md)。这是独立批次，不与技能实验合并成一个准确率。

## 最需要保留的执行检查

实测中有三个具体例子说明“返回合法答案”不足以构成执行依据：

| 证据 | Decider 实际判断 | 应由宿主检查的事实 |
| --- | --- | --- |
| 任务仅排队，结果文件不存在 | 不支持完成声明，却又选择 `finish` | 任务状态、产物存在且有效、跨问题答案是否一致 |
| 原测试断言被替换为 `assert True` | 认为没有削弱测试，并认为任务完成 | 原始验收条件是否仍被检查，真实测试与代码差异 |
| 只有一般咨询地址，没有发票地址 | 选择一般咨询地址，并判断主张得到支持 | 来源是否真的表达所需角色，无匹配时保留 `none/unknown` |

因此可采用这样的分工：

1. 应用或 Agent 收集当前证据，提供足够上下文和明确候选。
2. 决策模型选择标签、动作或评分，保留原始结果。
3. 执行器校验合法动作、权限、业务条件和关键证据。
4. 执行后检查实际结果，再决定继续、重判或转人工。

本轮 Jev 在 65 项可判定预期上全部符合，但样本小、主要为英文公开合成材料，且模板来自 Jev 技能库。没有证明其能对任意材料可靠验收，也没有验证置信度的生产校准。Decider 未针对这些模板调整表达或微调，不能仅据本轮断定所有误差都来自模型规模。

## 如何选模型与场景

- **想先取得可检查的结果：** 从工单分类、工具路由、合法动作选择开始；对业务真实样本增加无匹配、证据缺失、近似类别和上下文冲突用例。
- **考虑 Decider：** 本轮在上述明确候选任务中表现较好，支付批次的后端延迟也较低；适合进一步评估已有本地 GPU 服务上的有限候选任务。证据裁判和评分应先改进并重新验证。
- **考虑 Jev：** 本轮在证据核验和评分上更符合编写预期；适合托管判断与预筛，但执行权限和高后果业务条件仍由宿主验证。
- **需要开放式写作、代码生成或完整规划：** 本次没有测试这些能力。这里的模型输出是候选、判断和分数，生成内容、构造参数、执行工具与检查结果需要其他组件完成。

速度必须按同一部署路径和任务比较。技能实验中 Jev 从验证进程直连 TypeSafe，Decider 经过现有应用：客户端中位数分别为 119.9 / 164.6 ms；Decider 首个批量请求为 13.5 秒，明显影响均值。支付实验的 Jev 另经过 Lambda 转发，所以不能跨批次拼接耗时宣称通用加速倍数。费用没有足够依据比较。
