## 按具体业务理解这些应用

| 业务方向 | 代表项目 | 决策模型承担什么 | 业务收益应如何验证 |
| --- | --- | --- | --- |
| 浏览器业务操作 | Jev Ultrafast、WindTunnel、Stagehand、jev-browser-use | 从当前 DOM 元素或网站工具中选下一步；判断等待、继续、结束 | 真正完成搜索/填表/筛选的比例，完整耗时、恢复次数 |
| 桌面和移动端操作 | jev-desktop、Jev+AXe iOS 模拟器 | 根据宿主读取的控件与状态选动作 | 控件失效、窗口变化、状态过期时的恢复与最终结果 |
| 社交调研 | jev-social | 选择搜索、打开、读评论等动作 | 找到的有效来源、引用正确性、报告完成率 |
| 客服和邮件 | 邮件分流演示、jev-chat、Discord Bot | 分类、风险、意图、是否需要回复及候选排序 | 漏掉紧急消息、错误归档、误处罚、人工复核量 |
| 广告与内容运营 | 724 广告分析、SuperX、SponsorSkip | 标签化广告、评估草稿维度、定位赞助段落 | 标签一致率、时间边界误差；转化率需另做业务实验 |
| 数据库与检索 | pg-jev、JevQL、jevsearch | 对 SQL 候选行做语义过滤，对搜索候选重排 | 精确率、召回率、Hit@1、每千条成本及尾延迟 |
| 文档与原文证据 | JevPDF、Needle、官方抽取 cookbook | 选原文句段或字段；判断是否真的有答案 | 引用位置、原文一致性、无答案识别、证据遗漏 |
| 编码工作流 | 两种 Codex router、winnow、pi-warden、skill-gate | 模型路由、选上下文、选择压缩时机、挑 skills | 最终任务正确率、返工、真实费用、必要信息误删 |
| 代码质量与裁判 | jev-review、Supercov、LangSmith eval | 给检查排优先级、判断证据和规则满足情况 | 缺陷精确率/召回率、人工一致率、独立测试结果 |
| 游戏和仿真 | Tetris、Mario、Doom、Pac-Man、Wikiracing、交易回放 | 高频选择合法局部动作 | 留出种子的得分/完成率，与随机及专用算法比较 |
| 创作与动态界面 | Jevthoven、鲸背城市、jev-ui、ST-jeved、Jevinci | 音乐部件、剧情动作、界面分支、像素颜色等选择 | 规则一致性、交互延迟、盲评偏好和实际用户任务 |
| 本地部署与接口 | Laya、jevos、SemIf、jevify、MCP、SemDecide | 提供本地判断、统一调用或流水线接口 | 同题质量、设备成本、上下文上限、并发、校准 |

以客服售后为例，可以串成：**邮件分类 → SQL 找订单 → 选适用条款 → 浏览器定位操作 → 宿主执行 → 独立检查订单状态 → 文本模型写回复**。决策模型在这条链路里反复提供小判断；订单金额计算、权限、页面操作和结果证明都有各自负责的组件。

## 最有信息量的实际结果

以下为作者结果；只有 WindTunnel 数字由我们从公开 CSV 再计算过。它们没有包含本项目的 Strands Decider。

| 项目 | 观察到的效果 | 对结论的限制 |
| --- | --- | --- |
| WindTunnel | WebMCP：141/147 次尝试成功，49/49 个任务多数通过；DOM：76/147，25/49 | 相同模型组合，接口与执行框架不同；“49/49”不等于每次都成功 |
| WindTunnel 时间 | WebMCP agent 中位 3.210 秒，DOM 5.385 秒；包含重置/设置的 wall-clock 分别为 28.321、34.343 秒 | 不能把 agent 时间冒充完整运行时间 |
| Stagehand 原帖 | 作者 240 次测试，成功率 85%→95.4%，act 中位耗时 1.97→0.46 秒 | 原帖报告，尚未独立复现；存在文本模型回退 |
| jevsearch | 41 个查询，Hit@1 41%→83%；中位延迟 8.7→278ms | 更准确但更慢；候选召回率约 83%限制上限 |
| Tetris | Jev 三个种子消行 23/115/23；随机 0/0/0；启发式 118/118/116 | Jev 胜过随机，未胜过专用规则；调参种子与评估种子有重合 |
| jev-skill-gate | 4 个 Jev 案例，19 个预期技能都未隐藏；TF-IDF 同题隐藏 1 个 | Jev 只完成 4/20 案例，5 个技能仅显示名称；阈值曾由这些案例调整 |
| LangSmith 裁判 | 五个固定轨迹各重复 100 次，Jev 二元结果 500/500 与人工一致，均值约 0.44 秒 | 仅五个独立案例；低方差不等于在新任务上正确 |
| 实际业务分类比较 | 800 条提交信息：Jev 65.8%、Haiku 54.6%；450 条知识库：Jev 90.7%、Haiku 97.8% | 任务不同，胜负会反转；筛选后分数需连同覆盖率及相同样本比较 |
| LFM2.5-2.6B 推理实验 | 新鲜审计数据并行方式 72.2%，自回归 94.4% | 加速路线未通过作者准确率门槛，不能只展示速度 |

WindTunnel 的成本也存在统计口径区别：本次从 CSV 算出的每次尝试**平均估算费用**为 WebMCP `$0.001371`、DOM `$0.001669`。报告引用费用时应注明均值/中位数、是否含失败和用什么价格计算。

这些结果支持优先尝试有限选项分类、候选重排、原文选择和高频局部动作。它们也说明：**收益由问题、候选、执行框架、回退策略共同决定。**

## 页面后半段还有哪些值得研究的应用

除了项目表，108 个场景还包含这些具体方向，详见补充来源表：

- **网页语义 Ctrl+F / Needle**：从现有网页提取段落、判断相关性、定位原句。已找到原项目；直接 PDF 上传与 PDF 内高亮尚未实现。
- **Pac-Man**：大模型制定策略，Jev 选局部动作。原帖为早期演示，没有完整成绩表。
- **多角色发言和 TTS 语气**：根据会话状态选发言者、从预设声线/情绪中选择。原帖含设想和拟实现描述，不应全部算作已交付产品。
- **Discord 自动审核**：已找到实现，有审计日志、误报赦免和故障放行。所谓“学会不再误报”实际是把赦免案例加入后续上下文，不是重新训练或不再犯错的保证。
- **意图启动器、Emoji、剪贴板建议**：用户输入不断变化时，对已有候选重排；过期响应和可见确认比单次速度更影响体验。
- **语义高亮、AI 文本风格检测、麦克风暂停演示**：都是分类问题的交互包装。代码颜色正确、作者身份正确和“该禁言”是三种不同的验证目标。
- **实时视频特效与视频混剪**：先有转写或抽帧描述，Jev 选特效/片段，其他工具处理时间线、剪辑和渲染。作者混剪帖为 16 条素材选成 16 秒视频、不到 5 分钟的一次演示。
- **Jevinci 像素画**：已找到当前 `jev-paint` 实现；Jev 提供颜色分布，JavaScript 画笔算法生成纹理。画面效果同时来自模型和渲染器，原视频还注明 4 倍速。
- **关卡生成、驾驶/物理模拟、生命体征模拟**：代码维护合法性、物理和状态，模型选择受限动作或状态类别。原帖展示不能外推到真实车辆或临床效果。
- **日期提取、文档格式恢复、层次分类、语义特征**：官方 cookbook 分别将日期计算、文本渲染、树搜索、CatBoost 训练交给代码。决策模型负责读出字段、段落类型或特征。

特别是格式恢复：模型只判断两行是否该合并、块属于标题还是列表，代码可以在保留原文字词的同时重建 Markdown。这是一个比“请写一篇总结”更贴合决策模型能力的文档业务。

## 本地“Jev 类模型”不能混成一类

| 路线 | 例子 | 应怎样理解 |
| --- | --- | --- |
| 独立训练的模型 | Laya、Verdict、jevlike、jevos 的相应版本 | 有自己的权重、训练数据和能力边界，需独立评估 |
| 现有模型的推理方法 | SemIf、LitJev、OpenJev、LFM 并行字段方案 | 主要改变候选评分与输出方式；速度与正确率都可能改变 |
| 适配层与运行时 | jevify、System One Connector、SemDecide | 让接口可用、便于接入，不自动提高底层模型准确率 |
| 名称看似权重、实际主要发布代码 | `harshatheg/Qwen-2.5-1B-RLCD` | 本次 HF 文件清单未见权重，不能称为已发布 RLCD 模型 |

本地方案的毫秒延迟与云 API 的往返延迟包含不同开销。应先约束质量水平，再比较设备、短长输入、批次和并发；不能直接得出“同质量快几十倍”。

## 原页面自身的实验证据

页面末尾的五模型实验也应纳入理解。Jev 在该 BBH 子集为 138/160，但中文 LogiQA 为 16/20，低于 DeepSeek 的 19/20；Banking77 为 16/20；BFCL 的工具名选择五模型都达到 20/20，区分度不足。PR 数据测的是预先标注一致率，不是合并正确率。

Agent 配对小试验由 3/4 提升到 4/4，同时 API 调用从 35 增至 44，平均 API 耗时从 14.07 秒增至 16.35 秒。更早的 12 对试验则是 baseline 12/12、加入固定检查点 10/12。两者都被作者保留，说明“多加一层 Jev”不保证提升。

页面的校准试验还报告：160 题对 136 题，置信度至少 0.9 的 100 题仍错 8 题。因此需要按任务、问题类型和候选数量做留出验证。`score` 的等级期望、`noul` 的命题概率、`choice` 的候选分布和 confidence 字段不能混用。

## 与本项目 Jev / Strands Decider 实测怎样对应

此前本地验证对 32 个请求样例分别调用两种服务，共 64 次真实调用。每个模型返回 68 个判断；其中 65 个有预先写好的参考判据，3 个歧义题不计分。

| 事后按用途分组 | Jev | Strands Decider | 可以形成的初步判断 |
| --- | ---: | ---: | --- |
| 分类、意图与语义规则 | 13/13 | 13/13 | 优先做邮件、客服、内容标签的业务验证 |
| 工具、动作与模型路由 | 10/10 | 10/10 | 可继续用相同浏览器/游戏宿主对照 |
| 上下文保留与筛选 | 6/6 | 6/6 | 需进一步测误删后的真实任务效果 |
| 工作流状态与完成检查 | 8/8 | 7/8 | 要包含失败、缺前提、部分完成等状态 |
| 原文证据与不确定性 | 20/20 | 11/20 | 当前 Decider 的主要薄弱点，应单独扩样 |
| 按量表评分 | 8/8 | 3/8 | 当前 Decider 不宜直接沿用 Jev 评分阈值 |
| 合计 | 65/65 | 50/65 | 小样本参考一致率，非所有应用成功率 |

实际版本为 `jev-1.13.0` 和 `strands-decider-2B-hobson-v19`。分组是对现有题目的事后分析，没有增加独立样本。Jev 满分也不能推导成业务零错误。两条调用路径不同，原先延迟不应作为纯模型速度结论。

“有些 Decider 没完成”应分成几种情况看：服务没有返回、返回判断与参考不符、宿主动作未成功、业务前提本来不满足。**这批技能验证的 64 次调用都返回了有效结果；Decider 的 15 项差异属于判断不符，不是调用没完成。** 浏览器通关、游戏成绩、视频剪辑等端到端应用还没有由这一批模板测试覆盖。

已有原始结果：[验证报告](../README.md)、[按业务分组](../SCENARIO_SUMMARY.zh.md)、[逐条回执](../results/2026-10-12/receipts.jsonl)。此前六个演示的详细资料保留在 [DEMO_PROJECTS.zh.md](../DEMO_PROJECTS.zh.md)。

## 据此安排实际应用对照

以下是研究后得到的优先顺序，**尚未作为新的实测执行**。沿用现有 Jev/Decider 入口，在独立验证目录准备宿主，可以遵守“不改其他项目”的范围。

| 优先级 | 可复现业务 | 公平对照方法 | 必须记录 |
| --- | --- | --- | --- |
| 1 | 浏览器搜索与表单 | 同一网站副本、DOM、动作集合、辅助文本、回退和步数上限，只换决策入口；WebMCP 与 DOM 分组 | 最终页面断言、端到端成功率、耗时、重试与超时 |
| 1 | Tetris | 同一模拟器与合法落点，固定观察信息，使用未参与调参的种子；加入随机和启发式 | 消行、存活步数、p95 决策延迟、非法/过期动作 |
| 1 | 文档搜索与无答案 | 同一候选池，同一组中文/英文问题，加入缺证据、矛盾、近似但错误答案 | Hit@1、无答案精确率、错误证据接受率 |
| 2 | 邮件/客服分流 | 有交叉意图和业务代价的留出标注集；词法基线、Jev、Decider 同题 | 每类精确率/召回率、人工复核比例、严重漏判 |
| 2 | skills 与上下文选择 | 完整上下文、规则筛选、模型筛选三组，继续执行同一真实任务 | 任务正确率、必要信息误删、总 token 与返工 |
| 3 | PDF / SponsorSkip / SQL | 各自有真实行位置、时间边界或行级标签的样本 | 原文定位、区间误差、过滤准确率与吞吐 |
| 3 | 音乐、剧情、界面与绘画 | 决策规则和渲染组件固定，另做盲评或用户任务测试 | 约束违例、交互稳定性、偏好；不能只看“成功输出” |

首轮最有区分度的组合是 **浏览器 + Tetris + 原文检索/无答案**：前两项检验连续动作和实时性，第三项专门检验现有 Decider 差异最大的证据判断。分类和路由可以作为基础对照，但仅用简单样例容易全部满分，难以指导业务选型。
