# Jev 与 Strands Decider 全部测试总结

**对比结论：本轮实测中，Jev 在证据核验、多步浏览器操作和复杂候选比较上更稳；Decider 更适合类别清晰的任务分流和简单局部选择。完整模型路由、精确金融计算和最终业务验收，都不宜由这两个模型单独承担。**

- **需要查证据、操作网页或比较复杂候选，优先试点 Jev。** 证据核验为 20/20 对 11/20，浏览器完成数为 10/10 对 4/10；俄罗斯方块两种输入下均消除 19 行，Decider 分别为 0 行和 2 行。
- **需要工单分类、任务类型识别和清晰的局部路由，两者都可试点，Decider 是合理候选。** 基础分类双方均为 13/13，工具、模型和动作的局部选择均为 10/10；新增模型路由中的任务类型识别为 Jev 15/16、Decider 16/16，单次差异不足以判断普遍优劣。
- **需要 OpenRouter 式完整选模，采用分层设计。** 能力、成本和回退政策的首轮合计为 Jev 31/48、Decider 9/48；改成自然语言后为 31/48、8/48。让模型识别任务类型，由代码检查能力、预算与可用性，再排序和回退；该组合方案尚未完成端到端验证。
- **涉及金额与最终审批，两者都需要独立核验。** 两者均把同银行、同所有权类别的 18 万＋12 万美元存款误判为全部受保。某批满分、合法返回或较高置信度，都不能替代业务条件与执行结果检查。

以上“适合”表示值得继续试点，不是生产可靠性承诺。样本规模、输入表达和候选顺序会影响结果，各类测试不合并成一个总准确率。

汇总日期：2026-10-13。模型版本为 **Jev 1.13.0** 与 **Strands Decider 2B hobson v19**。本报告汇总已有实测，不增加模型调用，不修改原始结果。数据抽取与来源文件 SHA-256 见 [summary.json](summary.json)。

## 2. 真实浏览器：简单点击通过，不代表多步自动化通过

| 实际业务任务 | Jev | Decider | Decider 实际行为 |
|---|---:|---:|---|
| Wikipedia 搜索 Basel III | 2/2 | 0/2 | 在首页直接结束，没有搜索 |
| CFPB 查找信用卡账单争议处理指南 | 2/2 | 0/2 | 打开 Daily periodic rate 术语页后结束 |
| ECB 打开美元汇率详情 | 2/2 | 2/2 | 正确点击 USD，确认页面后结束 |
| FDIC 从保险说明打开 FAQ | 2/2 | 2/2 | 正确点击 FAQ，确认页面后结束 |
| FDIC BankFind 查询 JPMorgan Chase Bank | 2/2 | 0/2 | 点击 BankFind Suite 入口后结束，未提交查询 |

Jev 在银行任务中实际填入名称、点击 Search，结果中出现 JPMorgan Chase Bank, National Association，编号 **628**。第一次有重复填表和来回查看控件，共 10 步；第二次 6 步。完成率高不等于操作已经最优。

两个模型使用相同 Chromium 执行器，每步重新读取页面文字、DOM、URL 和最近操作；每轮最多 12 个选项，每任务最多 12 步、150 秒。搜索词由任务给定。模型不看截图，截图只留证；程序没有按答案筛选动作或代选下一步。

正式运行共 20 次任务，无 API 错误、浏览器动作错误或页面 JavaScript 错误。Decider 六次失败均是目标未完成就选 `finish`。因此，本轮失败不能解释成“服务没响应”或“浏览器点不动”。

**业务含义：** 在目标链接已经明显可见的单步导航上，两者都可试点；需要搜索、填表、识别结果、跨页面保持目标时，本轮优先 Jev。任务完成仍需独立核对实际页面结果，不能只相信模型的 `finish`。

## 3. 金融：区分语义分流、事实核验与精确计算

金融资料来自 FinancialPhraseBank、微软 FY2025 年报、FDIC 官方政策、ECB 实际汇率。除真实历史新闻外，待核验陈述和客户业务输入是构造案例，没有真实客户审批、转账或交易。

**财报核验。** 微软年报表格单位为百万美元，2025 年收入 281,724，2024 年 245,122。Decider 在原顺序和反转顺序中都支持两条错误陈述：“FY2025 收入 245.122 billion”和“FY2025 收入 281.724 million”。Jev 均识别为矛盾。由此可见，读到正确数字并不等于读对年份、单位与含义。

**存款保障。** 同一人、同一家受保银行、同一 single-owner 所有权类别，180,000 美元支票账户加 120,000 美元储蓄账户，合计 300,000 美元。题目条件下 250,000 美元受保、50,000 美元超限。两模型、两种顺序均判为全部受保。这是明确的业务错误，不能用新闻分类或模板满分掩盖。

**汇率处理。** 冻结的 ECB 日期为 2026-10-12，1 EUR = 1.1181 USD；EUR 10,000 的历史报表换算应为 USD 11,181.00，误用除法得到 8,943.74 应修正。Jev 六题均正确；Decider 多次要求获取付款可执行报价，即使事实写明是历史报表、不是付款。对于真正的付款需求，要求可执行报价则是正确选择。

**新闻分类。** 双方同错一道：数据集将出售业务、推进战略目标的新闻标为正面，两个模型均选中性。这反映与人工标签不一致，不能直接推断投资回报判断能力。

选项反转结果：

| 指标 | Jev | Decider |
|---|---:|---:|
| 原始顺序 | 28/30 | 22/30 |
| 反转顺序 | 28/30 | 24/30 |
| 两顺序合计，仍为 30 道独立题 | 56/60 | 46/60 |
| 仅换顺序就改变答案 | 0/30 | 2/30 |

**业务含义：** 新闻标签、资料初筛适合继续测试；Jev 可优先用于财报证据预审与处理路径建议。额度聚合、单位换算、汇率金额和最终付款条件应该有可审计的精确计算与核验，两者都不适合单独担任计算和审批系统。

## 4. 支付：步骤建议正确与业务能否结案要分开

主要配对批次有四个场景、每场景五步。每一步两者获得相同输入；原始选择与沙盒执行器实际动作分别保存。

| 支付场景 | Jev | Decider |
|---|---:|---:|
| USDC 已转账、订单未到账 | 5/5 | 5/5 |
| USDT 少付 | 5/5 | 4/5 |
| 稳定币退款、地址核验 | 5/5 | 4/5 |
| 商户结算延迟 | 5/5 | 5/5 |
| 合计 | 20/20 | 18/20 |

Decider 两个错误是：确认数已满足但少付，仍选择等待链上确认；退款地址未核验，选择检查通过。后一项被执行器改为地址核验，仍计作模型判断错误，不能把执行保护后的动作算成模型正确。

这批初始资料本来就缺少到账、补款、地址审批或结算等条件，双方都是 **0/4 完成资金业务与结案**。这里“未完成”是应有的待处理状态，与浏览器错误宣布完成的情况不同。

更早的 Decider/Jev 独立配对批次同样为 **18/20 vs 20/20**；另一个 Jev/GPT 配对批次中 Jev 也是 20/20。它们是同四个演示场景的重复观察，不扩充为更多独立金融案例。2026-10-11 的 Decider 输入优化实验由 14/20 变为 18/20，说明表达有作用，但不是稳定正确的保证；该批没有 Jev。

**业务含义：** 可把模型用于识别诉求、选择核验步骤、建议等待或升级。固定金额、确认数、地址、权限、记账和退款执行，应由业务系统检查。本轮没有验证真实资金流程的自动闭环成功率。

## 5. 俄罗斯方块：差距已经出现在单步候选比较

主比较使用 seed 42，每局上限 50 块，保留第一、二版；所有执行落点均为模型所选，没有策略代选。宿主共同提供合法落点与落点后指标，因此测试的是从已知后果中比较候选，而不是让模型从像素自行模拟物理。

| 模型 / 输入 | 落块 | 消行 | 有其他候选在给定指标上更好的选择 |
|---|---:|---:|---:|
| Jev / 数字字段 | 50 | 19 | 1/50 |
| Jev / 自然语言 | 50 | 19 | 1/50 |
| Decider / 数字字段 | 36 | 0 | 19/36 |
| Decider / 自然语言 | 43 | 2 | 22/43 |

“指标劣选”只针对已提供的下一块可出生、空洞、消行、堆高等指标，不证明长期最优策略。模型响应、实际落点和棋盘重放一致；后续显示修复未改变这些决策。

相同种子只固定方块顺序，模型走法不同会产生不同棋盘。为排除这个影响，另取三个失败棋盘，给两模型相同候选：

| 固定棋盘诊断 | Jev | Decider |
|---|---:|---:|
| 全候选、数字表达：指标劣选次数 | 0/3 | 3/3 |
| 全候选、自然语言：指标劣选次数 | 0/3 | 2/3 |
| 二选一、数字表达：选中较优项 | 6/6 | 3/6 |
| 二选一、自然语言：选中较优项 | 6/6 | 6/6 |

Decider 数字二选一在较优项排第一时 3/3，交换顺序后 0/3。自然语言修复了这些二选一案例，但在完整候选集合下仍有劣选。第三版规则筛选曾改善成绩，但已按要求移除，不能将其成绩当成模型本身能力。

**业务含义：** Jev 更适合在这种有限动作游戏里继续试验，但一枚种子不能证明普遍的规划能力；Decider 当前版本不适合直接负责这类多指标落点决策。仅改变表达，尚不能解决其候选比较问题。

## 6. 类 OpenRouter 模型选择：分流与完整路由要分开

新增测试共 **224 次真实决策调用**：首轮 32 题 × 两种顺序 × 两模型，共 128 次；随后对 24 道复合政策题，把候选 JSON 属性改写成自然语言，再运行 96 次。每对输入相同，保留全部候选，没有规则预筛选、代选或回退模型。标准答案不进入模型输入。

模型能力、上下文与标价取自 OpenRouter 公开目录；请求需求、健康状态、限流、延迟和零数据保留标记是测试设定，不代表供应商实际状态。没有调用 `openrouter/auto` 或被选中的下游模型。因此测的是**给定路由政策的一致率**，不是 OpenRouter 自身成绩、真实回答质量或账单节约。

当前 OpenRouter 文档把任务分类、模型排序、成本与限制、供应商回退分开处理。此前 Skills 的 10/10 混合了工具、模型和动作选择，其中真正模型路由只有“并发代码分析选推理模型”和“无可用能力时拒绝”两道，不能据此推断完整路由能力。

每类为 8 道独立题、两种顺序，共 16 次回答；语义分流本来就是自然语言，第二批未重复：

| 场景 | Jev 首轮 | Decider 首轮 | Jev 自然语言对照 | Decider 自然语言对照 |
|---|---:|---:|---:|---:|
| 普通文本、代码、数学、图片、长文档等任务分流 | 15/16 | 16/16 | 未重复 | 未重复 |
| 能力约束 | 7/16 | 3/16 | 7/16 | 2/16 |
| 成本与预算 | 9/16 | 2/16 | 9/16 | 2/16 |
| 可用性、回退与延迟偏好 | 15/16 | 4/16 | 15/16 | 4/16 |
| 后三类合计，24 道独立题 | **31/48** | **9/48** | **31/48** | **8/48** |

任务分流的单次差异不足以证明 Decider 普遍更强。Jev 有一次将普通改写选为补充材料；该题声明文本已提供，但没有附全文，存在表述歧义，按原定参考保留评分。

复合路由的错误比较明确：

- **有合格候选却拒绝。** 首轮 40 次应该选具体模型的机会中，Jev 有 9 次、Decider 有 37 次选 `no_route`。例如主模型故障而允许列表内还有健康备用模型，Decider 仍拒绝。自然语言对照中，Decider 全部 48 次都拒绝，仅有 8 次符合确实无候选的题目；回答不随顺序变化不能因此算作稳定可靠。
- **遗漏硬约束。** Jev 在图片请求中选择了仅支持文本的候选；30 万 token 请求的首轮原顺序中，两者都选择了容量为 131,072 的候选。
- **没有比较总成本。** 1,000 输入＋10,000 输出的题目中，Qwen 候选估算为 $0.00287，Mistral 为 $0.00259375。Jev 两种表达、两种顺序均选输入单价较低但总价较高的 Qwen；预算恰等于后者成本时还会超预算。Decider 则拒绝，虽然 Mistral 正好满足预算。

仅改候选表达没有改善总体结果。首轮 Jev 有 10/32 题随候选顺序改变回答，Decider 为 3/32；自然语言对照为 9/24 和 0/24，后者源于全部拒绝。Decider 报告的输入最多 1,485 tokens，低于服务公布的 4,096 上限，全部 API 调用成功，现有证据不支持将错误归因于超出该上下文上限。

**业务含义：** 两者可试点“请求 → 任务类别”；能力、上下文、预算、账号限制与可用性由代码检查，再按业务质量数据与明确策略排序、回退。Jev 在本轮复合政策上更好，但两者都不宜独自承担整套路由。过滤后再让模型选择的组合方案尚未实测，不能将这项建议写成已验证的新成功率。

## 7. 两个模型适合与不适合的场景

这里的“适合”表示本轮证据支持继续做业务试点，不表示已经达到生产验收标准。

| 具体业务用途 | Jev | Decider |
|---|---|---|
| 客服工单意图、账单/故障分类、新闻标签 | 适合试点 | 适合试点，当前最有支持的方向之一 |
| 已知工具、模型、动作 ID 的局部选择 | 适合试点 | 适合候选清晰、判断简单的试点 |
| 模型路由中的任务类型识别 | 本轮 15/16，可试点 | 本轮 16/16，可试点；小样本不构成通用优势 |
| 完整模型目录中的能力、成本、预算与回退选择 | 优于 Decider，但复合政策仅 31/48，不宜独立承担 | 经常错误拒绝可处理请求，不宜独立承担 |
| 选择能产生最佳实际回答的下游模型 | 未测试下游回答质量，需业务评测 | 同左 |
| 上下文相关性、资料保留建议 | 可辅助判断；实际删减后的任务质量未验证 | 同左，不能据 6/6 就自动删上下文 |
| 官方网页搜索、表单查询、多步资料收集 | 本轮优先，仍检查真实终点 | 暂不适合作为唯一控制者 |
| 原文引用、财报陈述、缺证据识别 | 本轮优先做预审 | 当前版本不宜独立担任证据裁判 |
| 代码审查、任务完成验收 | 可以提供辅助意见；独立检查代码与产物 | 已漏掉测试被改成 `assert True`，不宜作唯一验收门槛 |
| 紧急度、影响、风险等级评分 | 可试点，需要任务标注与阈值验证 | 当前模板仅 3/8，不宜直接套用 Jev 阈值 |
| 支付客服路径和核验步骤推荐 | 可试点 | 可在执行条件受系统检查时试点 |
| 金融金额、额度、汇率计算及资金审批 | 不宜由模型单独承担 | 不宜由模型单独承担 |
| 多指标数值比较、连续游戏动作 | 本轮优于 Decider，仍需多种子验证 | 当前实测不支持直接采用 |
| 长期交易策略、收益预测、真实自动交易 | 尚未验证 | 尚未验证 |
| 音乐、视频、绘画、桌面/iOS 自动化 | 仅研究过上游项目，未做本地双模型实测 | 同左 |
| 开放式报告、代码生成、完整参数构造 | 本次决策接口未验证此能力，需要生成组件 | 同左 |

选型应先看错误的业务代价，再看延迟：把一条咨询分到相邻队列，与把未核验退款判通过，不能只按“错一次”同等计价。两者 confidence 的定义与校准不能直接互比，本轮也没有验证生产阈值。

## 8. 速度与稳定性

| 测试与计时单位 | Jev | Decider |

| Skills：每请求客户端中位 RTT | 119.9 ms | 164.6 ms |
| 支付主要批次：每请求平均后端耗时 | 457.2 ms | 107.8 ms |
| 浏览器＋金融：每请求中位 RTT | 139.4 ms | 99.8 ms |
| 浏览器＋金融：每请求 P95 RTT | 182.3 ms | 303.7 ms |
| 游戏数字版：每次完整落点决策平均 | 256.1 ms | 1,511.5 ms |
| 游戏自然语言版：每次完整落点决策平均 | 251.1 ms | 1,414.5 ms |
| 模型路由首轮：每请求中位 RTT | 137.4 ms | 211.4 ms |
| 模型路由首轮：每请求 P95 RTT | 173.1 ms | 219.2 ms |
| 模型路由自然语言对照：每请求中位 RTT | 132.7 ms | 219.2 ms |

这些批次不能横向拼成固定加速倍数。Skills 中 Decider 首次批量请求为 13.5 秒，保留在均值中；支付 Jev 经 Lambda 转发；最新批次 Jev 直连、Decider 经现有网关；游戏一次落点常包含分组初选与决选，可能不止一次 API 请求。浏览器错误提前结束，也可能让失败任务看起来更快。

核心批次调用均返回有效结果：Skills 每模型 32/32，主要支付每模型 20/20，浏览器＋金融 Jev 96/96、Decider 82/82，模型路由两批每模型 112/112。支付连接修复前另有一次 Jev `ConnectionClosedError`，原始失败保留，不能据修复后的成功记录宣称没有发生过连接问题。

当前没有足够的费用、吞吐、并发和长期稳定性数据，不能得出“哪个始终更快、更便宜”。

历史第三版（规则筛选）在 seed 42/7/2026 的 50 块上限分别消行 10/19/16；在 seed 12345/314159 的 200 块上限分别消行 75/73。但这五局共有 **430/550 步**由程序策略选择，而非模型决策，属于混合系统成绩，不纳入两模型能力排名。

其他完成记录：

- 三模型、三版本的 5 块短局用于检查接入；其中两个模型的非规则版都能走完 5 块。这类短局不能替代 50 块质量测试，第三版数据也不能当纯模型成绩。
- AWS 的六个模型/版本组合、每局 3 块验证部署可用性，不代表长期游戏能力。
- 显示修复后的公网逐格检查覆盖 48 次真实落子，验证落定、消行、方块队列与慢网络补播；属于工程正确性检查，不纳入模型正确率。
- 支付系统较早的 GPT/Decider 固定流程和闭环测试没有 Jev，不能用于声称 Jev/Decider 对比。不同输入优化版本也不混算。
- 上游 README 的 **108 个场景**是目录研究范围，不是已复现 108 个业务工作流。74 个项目/目录的分析与 WindTunnel CSV 重算另有研究报告。作者的浏览器、音乐、视频、交易等结果均不作为本项目双模型实测分数。

## 10. 证据边界与可复核资料

样本偏小，Skills 主要是英文合成材料，且模板来自 Jev 技能库；业务分组为事后整理。评分题采用预先固定的 ±0.5 容差，个别 Decider 偏差刚超过阈值，不能把所有评分错误视为同等严重。金融新闻可能与训练数据重叠，其他金融参考由测试作者编写、未做专家盲审。浏览器仅覆盖有限动作、公开英文网站，不含视觉输入、登录和复杂动态业务；游戏主对照只有 seed 42。

浏览器采用更正后的独立评分：CFPB 正文为 “60 calendar days”，原脚本错写为 “60 days”。按保存页面重算后 Jev 从原始 8/10 更正为 10/10，Decider 仍为 4/10，未改变任何模型输入或动作，原始评分保留。SEC 403、FRED 控件回退在预检中排除，没有算成模型失败。

模型路由为英文小样本、自定应用政策；公开模型级能力不保证每个供应商端点都支持相同参数。成本仅按题目指定的文本 token 公式计算，未测缓存、媒体、隐藏推理用量或实际账单。自然语言批次是观察首轮结果后的表达诊断，不能当作独立留出集；没有测 OpenRouter Auto 的真实请求或下游模型回答质量。

结论限定于当前模型版本、输入方式、候选和执行框架。证据支持“哪类任务先试点、哪类错误需要防住”，还不支持推广成通用模型排名或生产承诺。
